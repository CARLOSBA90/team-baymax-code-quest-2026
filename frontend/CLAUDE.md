# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager: pnpm.

```bash
pnpm dev              # start Vite dev server
pnpm build            # tsc -b (typecheck all project refs) then vite build
pnpm preview          # preview production build
pnpm typecheck        # tsc -b only

pnpm check            # biome check (lint + format), no writes
pnpm check:fix        # biome check --write

pnpm test             # vitest run
pnpm test:watch       # vitest in watch mode
pnpm test:coverage    # vitest run --coverage (v8), enforces thresholds
```

## Architecture

React 19 + TypeScript + Vite SPA.

- `src/main.tsx` — entry point, mounts the app in strict mode. `src/Root.tsx` is the root route element.
- `src/router/` — `react-router-dom`. `router.tsx` exports `routes: RouteObject[]` and `router = createBrowserRouter(routes)`. `GuestRoute` protects `/auth/*` (guests only), `ProtectedRoute` protects `/dashboard/*`; both use `useGuardSession`. `/dashboard` index redirects to `/dashboard/roadmaps`; dashboard routes (`roadmaps`, `roadmaps/new`, `roadmaps/:roadmapId`) render under `DashboardLayout`. `/dashboard/roadmaps/new` is the assessment wizard, reached from the roadmaps empty-state CTA and the "Crear nueva ruta de aprendizaje" button; `roadmaps/:roadmapId` renders the placeholder `RoadmapDetailPage` (empty `<section aria-label="Detalle de la ruta">`, target of the list links). "Mis Rutas" stays active on all three.
- `src/pages/` — route pages (`auth/LoginPage`, `auth/RegisterPage`, `dashboard/RoadmapsPage` — the "Mis Rutas" list: state machine over `useRoadmaps()` (`RoadmapsListSkeleton` while loading, load error with "Reintentar", `RoadmapsEmptyState` when `counts.all === 0`, otherwise `RoadmapsFilterBar` + `RoadmapsTable` (`hidden lg:table`) and `RoadmapCardList` (`lg:hidden`) — both are always in the DOM); the active filter lives in `?status=` (`in_progress|paused|completed`, absent/invalid → `all`, changed with `replace`) and is applied in memory with `filterRoadmaps` (no refetch); an empty filter shows `ROADMAP_FILTER_EMPTY_MESSAGES[filter]` in a `role="status"` `<p>`; the header subtitle is `getRoadmapsSummary(counts)`. It also shows a one-shot success notice when `location.state` matches `ASSESSMENT_COMPLETED_STATE` (`lib/roadmaps-location-state.ts`) and then clears the state with `replace`; the notice is tied to the history entry (`location.key`), so back/forward to another Mis Rutas entry — or changing the filter, which `replace`s to a new entry — hides it; `dashboard/AssessmentPage` — the "Descubre tu ruta" questionnaire: breadcrumb, "Salir", and inside a `NebulaSurface` a state machine (skeleton while loading, load error with "Reintentar", empty-list message, wizard with a submit-error notice above it); a successful submit navigates to `/dashboard/roadmaps` with `replace` and the completed state).
- `src/components/` — `auth/` (forms, fields, notices; `TermsDialog` — the register terms modal opened from the "términos y condiciones" button next to the checkbox, which stays independent: "Aceptar" marks it and closes, any other close leaves it untouched; "Aceptar" is disabled until the text is scrolled to the end via the shared `useScrolledToEnd` hook (`src/hooks/shared/`, exported from the `@/hooks` barrel); the official terms text lives in `auth/terms-text.ts` as typed data — `TERMS_TITLE` (kept as "Términos y condiciones", the dialog's accessible name), `TERMS_INTRO`, `TERMS_SECTIONS` (`{ heading, paragraphs }`, rendered as `<h3>` + `<p>`), `TERMS_CLOSING` (after an `<hr>`); a `TermsParagraph` is a string or an array of string / `{ bold }` segments (rendered as `<strong>`), and `termsParagraphText()` flattens one to plain text; the platform name is a single `PLATFORM_NAME` constant there — all of it plus `TermsDialog` is exported from the `auth` barrel), `dashboard/` (the responsive dashboard shell: `DashboardSidebar` — `hidden md:flex`; landscape safe-area: width `w-[calc(16rem+env(safe-area-inset-left))]` with `pl-[max(1rem,env(safe-area-inset-left))]` so its own background extends under the notch, and `pb-[max(1.25rem,env(safe-area-inset-bottom))]`; prop `roadmapsCount` → pill on "Mis Rutas"; `SidebarNavItem` — optional `count` pill, visible number `aria-hidden` + `sr-only` ", {countLabel ?? count}" so the link's name is "Mis Rutas, 5 rutas" (`getRoadmapsCountLabel`); `SidebarUserCard`, `SidebarIcons`; mobile-only (`md:hidden`) `MobileTopBar` (`<header>`: brand + `UserAvatarMenu`) and `MobileTabBar` (`<nav aria-label="Navegación inferior">`, `MobileTabBarItem`s, no pill, not `fixed`); `UserAvatar` (initials) and `UserAvatarMenu` (`DropdownMenu` with "Cerrar sesión"); `RoadmapsEmptyState` — `NebulaSurface` + CTA + 3 steps, 1 column on mobile, 3 from `sm`), `roadmaps/` (the list pieces: `RoadmapsFilterBar` (`role="group"` "Filtrar rutas por estado", pressed-button pills with counts), `RoadmapsTable`, `RoadmapCardList` (`<ul aria-label="Tus rutas de aprendizaje">`) / `RoadmapCard` (stretched link + kebab `RoadmapRowMenu` over it), `RoadmapMonogram`, `RoadmapStatusBadge`, `RoadmapProgressBar` (`role="progressbar"`), `RoadmapActionLink`, `RoadmapRowMenu` (single danger item "Eliminar ruta" → `onDelete()`; it never deletes by itself — `RoadmapsTable`/`RoadmapCardList`/`RoadmapCard` take a required `onDelete: (roadmap) => void` and close it over their row; `RoadmapsPage` passes a temporary no-op until the delete flow is wired), `DeleteRoadmapDialog` (controlled confirmation on `ui/Modal`: `{ roadmap | null, pending, errorMessage, onCancel, onConfirm }`, open while `roadmap !== null`; named by the h2 "¿Eliminar {name}?" and described by the "Se perderán tu progreso y tus entregas…" paragraph; `errorMessage` → `AuthNotice` error (`role="alert"`); "Cancelar" (`GhostButton`) + red "Eliminar ruta" (`PrimaryButton tone="danger"`, `loadingLabel` "Eliminando…"); while `pending` both buttons are disabled and X/Esc/backdrop are ignored), `RoadmapsListSkeleton`, `RoadmapsIcons` incl. `PlusIcon`), `assessment/` (the questionnaire wizard: `AssessmentWizard`, `AssessmentWizardSkeleton`, `AssessmentProgress`, `AssessmentQuestion`, `AssessmentOptionCard`, `AssessmentNav`, `AssessmentIcons`, and the `useAssessmentWizard` reducer hook), `layouts/` (`AuthLayout`, `DashboardLayout` — `h-dvh overflow-hidden` row: sidebar + a column with `MobileTopBar` / scrolling `<main>` (`overflow-auto`, `px-5 pt-4 pb-8 md:pl-12 md:pr-[max(3rem,env(safe-area-inset-right))] md:pt-11 md:pb-[max(2.5rem,env(safe-area-inset-bottom))]` — the right/bottom `env()` insets cover the notch and home indicator at md+ with `viewport-fit=cover`, where the mobile bars are hidden) / `MobileTabBar`; it calls `useRoadmaps()` for the sidebar pill, sharing the page's query cache; pages inside `<main>` use `min-h-full`, not `h-full`, so they grow with their content and `main` scrolls), `ui/` (incl. `NebulaSurface` — the dotted `.empty-state-surface` panel; `grow shrink-0` so it fills the free height on desktop but never shrinks below its content (it has `overflow: hidden`, so a shrinking flex item would clip the centered content top and bottom); `px-5 py-8 md:p-12`. `DropdownMenu` — WAI-ARIA menu button (`triggerLabel`, `trigger`, `items: { id, label, onSelect, tone?, icon?, disabled? }[]`, `align`): opens on click/Enter/Space/ArrowDown (ArrowUp → last item), cyclic arrows + Home/End, Esc returns focus to the trigger, closes on outside `pointerdown` or when focus leaves; disabled items are skipped. `Modal` — generic controlled shell over native `<dialog>` + `showModal()`: blurred backdrop, glass panel and an X button labelled "Cerrar diálogo"; no title/footer, the consumer passes heading and buttons as `children` and names it with `aria-labelledby`/`aria-label`; closes via `onClose` on X, Esc (`cancel`, default prevented) and backdrop click; locks page scroll with `overflow-hidden` on `<html>` and returns focus to the opener; both are released whenever `open` turns `false`, even if the browser already closed the `<dialog>` natively).
- `src/lib/auth-client.ts` — Better Auth client (`better-auth/react`). `src/lib/auth-errors.ts` — auth error mapping. Roadmaps helpers (from the `@/lib` barrel): `roadmap-filters.ts` (`RoadmapFilter`, `ROADMAP_FILTERS`, `ROADMAP_STATUS_PARAM`, `parseRoadmapFilter`, `filterRoadmaps`), `roadmap-labels.ts` (status/level/action labels, `ROADMAP_FILTER_EMPTY_MESSAGES`, `getRoadmapsSummary`, `getRoadmapsCountLabel`, `getRoadmapCoursesSubtitle`), `roadmap-presentation.ts` (`getRoadmapMonogram`, `getRoadmapAccent`, `getRoadmapPath`, `clampProgress`).
- `src/api/` — axios `client.ts`, `errors.ts` (`getApiErrorMessage`), `queryClient.ts`, `services/` (auth/users, assessments — `GET /assessments/questions` and `POST /assessments/submit` through `get`/`post` of `@/api/client`; roadmaps — `getRoadmaps()` with no params, returns `{ items, meta, counts }` mapped from snake_case DTOs by `toRoadmapSummary`), and `queries/` (TanStack React Query hooks + query keys; `auth`, `users`, `assessments`, `roadmaps` — `useRoadmaps()` on `roadmapsKeys.list()` with `staleTime: ROADMAPS_STALE_TIME` (30 s, so remounts reuse the cache); `useSubmitAssessment` invalidates `roadmapsKeys.all` on success (fire-and-forget, so the new roadmap shows in Mis Rutas and the sidebar pill without delaying the page's navigation) — mutations that change roadmaps must invalidate explicitly). `getRoadmaps()` calls the real backend: `apiClient.get("/roadmaps", { params: { limit: ROADMAPS_LIST_LIMIT } })` → `GET /api/v1/roadmaps?limit=100` (Better Auth session cookie). It uses `apiClient` directly, not `get`/`getPage`, because those unwrap `data` and would drop `meta`/`counts`. `ROADMAPS_LIST_LIMIT` = 100 = the backend `MAX_PAGE_SIZE` (above it the backend answers 400); only page 1 is requested and filtering is in memory, so a user with more than 100 roadmaps only sees the newest 100 (the counts/pill stay global).
- `src/schemas/` — zod schemas. `src/types/` — shared types.
- `src/hooks/` — shared React hooks, exported from the `@/hooks` barrel (`shared/useScrolledToEnd` — latches `hasReachedEnd` once a scroll container reaches its end within an 8px threshold, or immediately when the content does not overflow; while the element has no layout — `clientHeight === 0`, e.g. inside a `<dialog>` before `showModal()` — it does not evaluate, and the `ResizeObserver` re-checks once it gets size).
- `@/*` aliases `./src/*` (in both `vite.config.ts` and `tsconfig.app.json`).

## Conventions

When creating or modifying any file in `src/`, always invoke the `frontend-conventions` skill (`.claude/skills/frontend-conventions/SKILL.md`): imports only via `@/` or `./`, imports through the folder's `index.ts` barrel, and `PropsWithChildren` for `children`. Biome (`noRestrictedImports`) enforces the first two rules.

Hook location: every **new** UI/state hook used by components goes in `src/hooks/<folder>/` (create the folder if needed, e.g. `shared/`) and is exported from the `src/hooks/index.ts` barrel (`@/hooks`). React Query hooks (`useQuery`/`useMutation`, e.g. `useRoadmaps`, `useDeleteRoadmap`) stay in `src/api/queries/<domain>/`. Existing hooks elsewhere (e.g. `useAssessmentWizard`, `useGuardSession`) are not moved.

## Styling

Tailwind v4 via `@tailwindcss/vite`, CSS-first (no `tailwind.config.js`). Design tokens are declared in `src/index.css` under `@theme`; add or change theme values there.

`PrimaryButton` has `variant` (`form` = `w-full`, `cta` = `w-fit px-6`) for width and `tone` for color: `accent` (default, violet) or `danger` (red, destructive actions) — `bg-danger-solid shadow-danger focus-visible:border-danger focus-visible:shadow-ring-danger`, from the `--color-danger-solid` / `--shadow-danger` / `--shadow-ring-danger` tokens (`danger-solid` is darker than the `danger` text color so white text stays AA). The app has a single dark theme (`color-scheme: dark`); there is no light theme to mirror tokens into.

## Testing

Vitest 5 + jsdom + Testing Library (config in the `test` block of `vite.config.ts`).

- Specs live in `__tests__/` folders beside the code: `src/**/__tests__/**/*.spec.{ts,tsx}`.
- `globals: false` — import `describe`, `it`, `expect`, `vi`, etc. from `vitest` explicitly. `src/test/setup.ts` loads `@testing-library/jest-dom/vitest` and runs `cleanup` after each test. `restoreMocks` and `unstubGlobals` are on.
- Render components with `renderWithProviders(ui, { route })` from `src/test/renderWithProviders.tsx` (fresh `QueryClient` with no retries + `MemoryRouter`).
- `renderWithProviders` also accepts `initialEntries`/`initialIndex` (entries may carry `state`; `initialEntries` wins over `route`) and a preloaded `queryClient`; it returns the `queryClient` it used. `createTestQueryClient()` builds the same no-retry client.
- Test fixtures live in `src/test/fixtures/` (`assessments.ts` — questions + `buildAssessmentResultMock`; `api-errors.ts` — `buildAxiosError`, `buildNetworkError`; `roadmaps.ts` — `ROADMAP_SUMMARY_DTOS` (wire-shape snake_case DTOs), `buildRoadmapsListResponseDto`, `buildRoadmapSummary`, `buildRoadmapsListResult`, `ROADMAPS_LIST_RESULT`, `EMPTY_ROADMAPS_RESULT`). No barrel: import them directly (`@/test/fixtures/assessments`) and **only from specs** — production code never imports fixtures.
- Mock the API layer with `vi.mock("@/api/services", ...)` in page/component specs; the assessments hooks spec (`api/queries/assessments/__tests__/assessments.spec.tsx`) mocks `@/api/client` instead. **Any spec that renders `DashboardLayout` or `RoadmapsPage` (incl. `AssessmentPage` specs that navigate to Mis Rutas, and `router` specs) must mock `getRoadmaps`** in its `vi.mock("@/api/services")` factory, otherwise it hits the real axios client. `roadmaps.service.spec.ts` mocks `@/api/client` as `{ apiClient: { get: vi.fn() } }`. The logout flow is covered end to end in `router/__tests__/logoutFlow.spec.tsx` (real `useLogout`, guards and pages; only `useSession` — an external store — and `signOut`/`getRoadmaps` are mocked). `GuestRoute`/`ProtectedRoute` specs mock `@/router/useGuardSession`; only `useGuardSession.spec.tsx` mocks `@/lib/auth-client` (`authClient.useSession`).
- `<dialog>` in jsdom: `src/test/setup.ts` polyfills `HTMLDialogElement.prototype.showModal`/`close` (`showModal` sets `open` and focuses the first focusable descendant; `close` clears `open` and dispatches `close` synchronously). No top layer, focus trap, inertness or native Esc — those are manual QA only. Simulate Esc with `fireEvent(dialog, new Event("cancel", { cancelable: true }))`. jsdom has no layout, so scroll overflow is simulated with `vi.spyOn(HTMLElement.prototype, "scrollHeight" | "clientHeight", "get").mockReturnValue(…)` **before** opening, then `region.scrollTop = N` + `fireEvent.scroll(region)`; without the spies `clientHeight` is 0, which `useScrolledToEnd` treats as "no layout yet" and never evaluates — so the terms "Aceptar" stays disabled. To simulate content that fits, mock equal heights (e.g. `300`/`300`).
- **Known debt — `rerender` loses providers:** the `rerender` returned by `renderWithProviders` is Testing Library's raw one, so it re-renders the UI **without** `QueryClientProvider`/`MemoryRouter`; the root element type changes and React remounts the whole tree (state and effects reset). Until the helper is fixed, change props through a stateful test wrapper (e.g. trigger button + `useState`, as in `Modal.spec.tsx`/`TermsDialog.spec.tsx`) instead of `rerender`.
- Roadmaps list / shell queries: the table and the card list are both in the DOM (CSS hides one), and the sidebar and tab bar both have a "Mis Rutas" link — always scope with `within(table)` / `within(cardList)` / `within(screen.getByRole("navigation", { name: "Navegación principal" | "Navegación inferior" }))`. The sidebar link's name is "Mis Rutas" while loading and "Mis Rutas, N rutas" once loaded (`/^Mis Rutas(, \d+ rutas?)?$/`); the tab bar's is exactly "Mis Rutas". In table specs match the name with `getByText(name, { selector: "p" })`. Several `banner`s exist in jsdom (page headers inside `main` count too) — reach the top bar via the "Menú de usuario de …" button + `closest("header")`. The skeleton, the empty-filter message and the success `AuthNotice` all use `role="status"`, so find the notice by text.
- Layout is not computed in jsdom: responsive/overflow fixes are asserted via classes (`toHaveClass`), and real clipping is manual QA.
- Fake timers: Testing Library only detects Jest fake timers, so with `vi.useFakeTimers()` also stub a global `jest` (`vi.stubGlobal("jest", { advanceTimersByTime: vi.advanceTimersByTime.bind(vi) })`). See `useFakeTimersForTestingLibrary` in `RegisterPage.spec.tsx`.
- Coverage is scoped to the roadmaps list (`lib/roadmap-{filters,labels,presentation}.ts`, `api/services/roadmaps.service.ts`, `api/queries/roadmaps/**`, `components/roadmaps/**`, `components/ui/DropdownMenu.tsx`), auth code (`lib/auth-errors.ts`, `components/auth/**`, `pages/auth/**`, router guards), the dashboard shell (`lib/user-initials.ts`, `components/dashboard/**`, `components/ui/NebulaSurface.tsx`, `components/layouts/DashboardLayout.tsx`, `pages/dashboard/**`, `router/{GuestRoute,ProtectedRoute,router}.tsx`, `router/useGuardSession.ts`) and the assessment wizard (`lib/assessment-labels.ts`, `lib/roadmaps-location-state.ts`, `components/assessment/**`, `components/ui/GhostButton.tsx`), plus `components/ui/Modal.tsx` and `hooks/**` (the terms modal pieces are already under `components/auth/**`) — currently 57 spec files, 581 tests, including `components/auth/__tests__/{PasswordField,PrimaryButton,TermsDialog}.spec.tsx`, `components/roadmaps/__tests__/DeleteRoadmapDialog.spec.tsx`, `hooks/shared/__tests__/useScrolledToEnd.spec.tsx`, `components/ui/__tests__/Modal.spec.tsx`, `components/dashboard/__tests__/{SidebarNavItem,SidebarUserCard,DashboardSidebar,RoadmapsEmptyState}.spec.tsx`, `components/assessment/__tests__/*.spec.{ts,tsx}` (incl. `AssessmentWizardSkeleton`), `lib/__tests__/roadmaps-location-state.spec.ts` and `pages/dashboard/__tests__/{AssessmentPage,RoadmapsPage}.spec.tsx` (`api/queries/assessments/__tests__/assessments.spec.tsx` runs but the rest of `api/**` is outside coverage) — with thresholds 80% lines/functions/statements and 70% branches. Widen `coverage.include` as more code gets tests.

## Linting & formatting

Biome (`@biomejs/biome`) replaces ESLint/Prettier entirely — there is no ESLint config in this repo. Config is in `biome.json`:

- 2-space indent, double quotes, semicolons, trailing commas, 100-char line width.
- `a11y` recommended rules are enabled and enforced — decorative `<svg>` elements need a `<title>`, and links need non-ambiguous accessible text.
- `useAwait`, `noUnusedImports`, `noUnusedVariables`, `useImportType`, `useConst` are errors.
- `organizeImports` runs as a formatter action.
- Run `pnpm check:fix` before committing to apply both lint fixes and formatting.
