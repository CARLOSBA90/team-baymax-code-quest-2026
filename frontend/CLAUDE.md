# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager: pnpm.

```bash
pnpm dev              # start Vite dev server
pnpm build            # tsc -b (typecheck all project refs) then vite build
pnpm preview          # preview production build
pnpm typecheck        # tsc -b only

pnpm check            # biome check (lint + format), no writes
pnpm check:fix        # biome check --write

pnpm test             # vitest run
pnpm test:watch       # vitest in watch mode
pnpm test:coverage    # vitest run --coverage (v8), enforces thresholds
```

## Architecture

React 19 + TypeScript + Vite SPA.

- `src/main.tsx` — entry point, mounts the app in strict mode. `src/Root.tsx` is the root route element.
- `src/router/` — `react-router-dom`. `router.tsx` exports `routes: RouteObject[]` and `router = createBrowserRouter(routes)`. **Pages and layouts are code-split with the data router's `lazy` route property** (`lazy: async () => ({ Component: (await import("@/pages/auth/LoginPage")).LoginPage })`-style): `AuthLayout`, `DashboardLayout` and every page are separate chunks; `Root`, `GuestRoute`, `ProtectedRoute` and the index `<Navigate>` stay eager. The router resolves all matched `lazy` routes in parallel **before** committing a navigation, so there is no `Suspense` boundary and no half-painted shell: on client navigations the current page stays until the next chunk arrives; on the initial load the root's `hydrateFallbackElement` (`FullScreenSpinner` — `role="status"` "Cargando…", the same spinner the guards show while the session loads) is rendered. The root route's `errorElement` is `RouteErrorBoundary` (stale-chunk reload, see *Bundle / chunks*). `lazy` only works with a data router (`createBrowserRouter`/`createMemoryRouter`), never with `<MemoryRouter>` + `useRoutes`. The `import()`s point at the concrete file, not the barrel (a barrel would put every page in one chunk) — `biome.json` has an `overrides` entry that relaxes the barrel pattern of `noRestrictedImports` for `src/router/router.tsx` only (the `../` ban still applies). `GuestRoute` protects `/auth/*` (guests only), `ProtectedRoute` protects `/dashboard/*`; both use `useGuardSession`. `/dashboard` index redirects to `/dashboard/roadmaps`; dashboard routes (`roadmaps`, `roadmaps/new`, `roadmaps/:roadmapId`) render under `DashboardLayout`. `/dashboard/roadmaps/new` is the assessment wizard, reached from the roadmaps empty-state CTA and the "Crear nueva ruta de aprendizaje" button; `roadmaps/:roadmapId` renders `RoadmapDetailPage` (target of the list links, see `src/pages/`). - **Bundle / chunks:** `package.json` declares `"sideEffects": ["**/*.css"]` so barrels tree-shake (without it the guards' `@/components/auth` import dragged the auth forms + zod into the entry). `vite.config.ts` `build.rolldownOptions.output.codeSplitting.groups` puts stable vendors in their own long-cached chunks: `react-vendor` (react, react-dom, scheduler, react-router), `query-vendor` (`@tanstack/*`), `auth-vendor` (better-auth + deps). zod only ships in the auth pages' shared chunk. Don't raise `chunkSizeWarningLimit` to hide a warning — split instead. If you add a module with import-time side effects that must run even when nothing is imported from it, list it in `sideEffects`. **Stale chunks after a deploy** (an open tab asks for an old chunk hash): the root route's `errorElement`, `router/RouteErrorBoundary.tsx`, detects a failed `lazy()` import with `isChunkLoadError` (Chromium/Firefox/Safari "dynamically imported module" messages and Vite's "Unable to preload CSS") and calls `reloadOnceForChunkError()` from `lib/chunk-error-reload.ts` (`@/lib`), showing `FullScreenSpinner` meanwhile. It reloads at most once per `CHUNK_RELOAD_WINDOW_MS` (10 s; timestamp in `sessionStorage` under `CHUNK_RELOAD_STORAGE_KEY`, plus an in-memory flag so a failing storage — or StrictMode's second effect — still reloads only once). When blocked by the window, or for any other route error, it shows a `role="alert"` Spanish notice + `GhostButton` "Recargar". React Router commits a navigation whose `lazy` fails (it pushes the target URL, then renders the `errorElement` there), so `location.reload()` reloads the **target** route. **There is deliberately no global `vite:preloadError` listener**: every `import()` in the app goes through router `lazy` (the devtools one is dev-only), and such a listener fires while the navigation is still pending and would reload the *origin* URL, losing the user's intent. If you add a non-router `import()`, handle its failure locally rather than reintroducing a global reload.
- `src/hooks/` — shared React hooks, exported from the `@/hooks` barrel (`shared/useScrolledToEnd` — latches `hasReachedEnd` once a scroll container reaches its end within an 8px threshold, or immediately when the content does not overflow; while the element has no layout — `clientHeight === 0`, e.g. inside a `<dialog>` before `showModal()` — it does not evaluate, and the `ResizeObserver` re-checks once it gets size; `roadmaps/useDeleteRoadmapNotice` — `{ message, show(message) }`, the notice is stored with the current `location.key` and dropped as soon as the key changes, so it never reappears when returning to that entry). New UI/state hooks go here (`src/hooks/<folder>/`); React Query hooks stay in `src/api/queries/`.
- `@/*` aliases `./src/*` (in both `vite.config.ts` and `tsconfig.app.json`).

## Conventions

When creating or modifying any file in `src/`, always invoke the `frontend-conventions` skill (`.claude/skills/frontend-conventions/SKILL.md`): imports only via `@/` or `./`, imports through the folder's `index.ts` barrel, and `PropsWithChildren` for `children`. Biome (`noRestrictedImports`) enforces the first two rules.

Hook location: every **new** UI/state hook used by components goes in `src/hooks/<folder>/` (create the folder if needed, e.g. `shared/`) and is exported from the `src/hooks/index.ts` barrel (`@/hooks`). React Query hooks (`useQuery`/`useMutation`, e.g. `useRoadmaps`, `useDeleteRoadmap`) stay in `src/api/queries/<domain>/`. Existing hooks elsewhere (e.g. `useAssessmentWizard`, `useGuardSession`) are not moved.

## Styling

Tailwind v4 via `@tailwindcss/vite`, CSS-first (no `tailwind.config.js`). Design tokens are declared in `src/index.css` under `@theme`; add or change theme values there.

`PrimaryButton` (`components/ui/`) has `variant` (`form` = `w-full`, `cta` = `w-fit px-6`) for width and `tone` for color: `accent` (default, violet) or `danger` (red, destructive actions) — `bg-danger-solid shadow-danger focus-visible:border-danger focus-visible:shadow-ring-danger`, from the `--color-danger-solid` / `--shadow-danger` / `--shadow-ring-danger` tokens (`danger-solid` is darker than the `danger` text color so white text stays AA). The app has a single dark theme (`color-scheme: dark`); there is no light theme to mirror tokens into.

**Responsive classes are mobile-first**: the base utility is the mobile value and `sm:`/`lg:` override it. **Never put two base utilities for the same property on one element** (e.g. `h-11` from a shared constant + `h-12` from the consumer, or `flex` + `hidden`): Tailwind resolves them by CSS order, not class order, so the result is arbitrary. That is why `LINK_SHAPE` (`components/roadmap-detail/link-classes.ts`) carries no height, padding or width, `ItemStateDot` has no display of its own, and a `className` added to a shared piece should only bring `sm:*`/`lg:*`, `order-*`, `self-*`, `mt-*` or `[grid-area:*]`. `GhostButton` has `size` `sm` (`h-10 px-4`), `md` (default, `h-11 px-5`) and `lg` (`h-12 px-5`, the 48px mobile touch target).

Roadmap detail tokens (`@theme` block «Detalle de ruta (design.md §16)»): `--container-detail` (920px → `max-w-detail`), `status-paused-text`/`status-paused-bar`, `status-completed-text` (violet chips/% reuse `accent-soft`), `rail`/`rail-done`, `node-pending`/`node-next`/`node-done`/`node-done-check`, `bg-item{,-next,-done}`, `border-item{,-active,-next,-done}`, `bg-next-step`/`border-next-step`, `bg-paused-banner`/`border-paused-banner`, `thumb-{from,to}`/`thumb-done-{from,to}`, `done-{bg,border,halo,dots}` and `--shadow-node-next`. Components in `components/roadmap-detail/` use only these tokens (no hex/rgba literals, the completed illustration included). The green Nebula variant is the CSS modifier `.empty-state-surface--success` (outside `@theme`), which redefines `--color-empty-{bg,border,halo,dots}` with `var(--color-done-*)`; `NebulaSurface` itself has no tone prop. **Tailwind v4 prunes `@theme` variables no utility uses**: a token referenced only through `var()` in hand-written CSS is emitted only because that CSS rule is in the bundle (the `done-*` case); a token with no consumer at all is dropped from `dist` until a utility uses it — check `dist/assets/*.css` after `pnpm build` when adding tokens.
